## TL;DR

新しい DEX や Perp DEX を作る際、最も起こりやすい誤りはチェーン選定を性能ランキングと考えることだ。存続を決めるのは公称 TPS ではなく、次の5条件が同時に成立するかである。

1. 継続的な取引フローがある。
2. 利用可能なステーブルコインと担保がある。
3. 長期にわたり気配値を出すマーケットメーカーがいる。
4. ウォレット、取引端末、コミュニティ、取引所からの集客がある。
5. オラクル、清算、保険基金、極端な相場に対応できる。

利用者提供の2026-09-27時点のデータに基づく選択は明確だ。

- **新規現物 DEX：Solana を優先、Base が次点。Binance エコシステムの集客経路があれば BSC を検討する。**
- **新規 Perp DEX：Base と Solana を優先。取引所級のインフラをゼロから作りたくなければ Hyperliquid HIP-3 を選ぶ。**
- **Ethereum は資本・決済層に適し、個人向け Perp の最初の実行層には適さない。**
- **Monad と Sui は第2の選択肢に向くが、マーケットメイクと資金の確約なしに唯一の主戦場にするべきではない。**

全チェーンのデータ、プロトコル比較、リスクの定義は[「主要パブリックチェーンの新規 DEX / Perp DEX：長期チェーン選定研究」](/research/mainstream-chain-dex-perp-dex-long-term-chain-selection-research)を参照。

## チェーン選定は技術試験ではなく、市場参入の問題

チェーンの性能は理論上の上限を決めるが、新規チームがまず直面するのは立ち上げ時の下限だ。低遅延、高処理量、低手数料があっても、ステーブルコイン、マーケットメーカー、取引者、集客経路が不足すれば使える市場は成立しない。

だから「より多くのチェーンに展開する」ことは、リスク分散ではなく流動性の分断となりがちだ。1チェーン増えるごとに次の負担が生じる。

- LP とマーケットメイクの在庫。
- オラクルと指数価格。
- 清算と保険基金。
- クロスチェーン入金と資金配分。
- ウォレット、フロントエンド、運用対応。
- 現地コミュニティと成長コスト。

独立した集客入口がなければ、多チェーン展開はすべての市場を薄くするだけだ。

## 実行可能な3つの経路

### 経路1：Solana で高頻度取引と新規資産の発見

Solana の最大の優位性は TVL ではなく取引フローだ。提供されたデータでは、30日間の現物 DEX 取引量は約 **767.1億ドル**、DEX / TVL 回転率は約 **11.57x** で、Ethereum、BSC、Base を明確に上回る。

適する用途は次のとおり。

- 新規資産の初回発行とロングテール取引。
- 高頻度、少額、ボット取引。
- 現物と Perp の共通口座。
- 低遅延の注文板と清算。
- ウォレット、アグリゲーター、取引端末への組み込み。

ただし、多い取引フローが新規プロトコルへ自然に流れるわけではない。Raydium、Orca、Jupiter、Drift はすでに認知とルーティング入口を押さえている。新規チームには資産発行、ウォレット入口、気配値、地域ユーザー、取引ツール、新市場の発見機構の少なくとも1つの独占資源が必要だ。

Solana は「高い上限と激しい競争」の選択だ。集客力がなければ、取引量が大きいほど、自分も容易に一部を獲得できるという錯覚を生みやすい。

### 経路2：Base で EVM、USDC と商品層の革新

Base の価値は最大取引量ではなく、EVM ツール、USDC、Coinbase 関連の集客と消費者向け体験を同じ環境に置く点にある。

EVM チームに適する用途は次のとおり。

- RFQ、Intent、Solver 取引。
- USDC 決済の現物や Perp。
- ソーシャル取引、コピー取引、統一口座。
- RWA、ステーブルコイン、準機関向け OTC。
- 現物、融資、利回り戦略の組み合わせ。

Base でもう1つの Aerodrome を複製するべきではない。既存流動性を再利用し、ルーティング、リスク管理、口座、戦略、顧客関係に商品の優位性を置く方が合理的だ。基礎流動性は借りられるが、集客と体験は自ら掌握する必要がある。

### 経路3：Hyperliquid 上で特定分野の Perp 市場

Hyperliquid を複製するには、注文板、マッチング、オラクル、資金調達率、保険基金、清算、マーケットメイク、ウォレット、API、市場発行を作り直す必要がある。数個のコントラクトの配置ではなく、取引所全体の構築だ。

資源が限られるチームには、HIP-3 を使い、既存流動性と取引習慣の上で次を作る方が合理的だ。

- 商品、指数、株式の Perp。
- 地域資産と新興資産。
- 特定コミュニティ向け市場。
- 調査、戦略、API、専門端末。
- 特定分野向けの口座層とリスクツール。

一部のインフラ支配を手放して、立ち上げコストを下げる経路だ。問いも「新しい取引所をどう作るか」から「どの取引需要が未対応か」に変わる。

## BSC、Ethereum、新興チェーンが標準解ではない理由

### BSC：集客力があれば強く、なければ難しい

BSC は多くの個人利用者、ステーブルコイン、高頻度取引を持つが、PancakeSwap と Binance が強い入口を築いている。ウォレット、KOL、取引ボット、地域市場があれば最上位の候補になる。技術力のみでは、安い手数料で既存のネットワーク効果を破ることはできない。

### Ethereum：資本の中心であり、個人向け実行層ではない

Ethereum は依然として、最も深い優良資産の流動性、ステーブルコイン、機関資金、安全性の基盤を持つ。資産発行、プロトコル財庫、高額決済、クロスチェーン流動性の中心に適する。

ただし個人向け Perp では手数料、承認速度、清算対応に優位性がない。合理的な構造は次のとおり。

> Ethereum が資産・資本層を担い、Base、Solana、Hyperliquid が取引実行層を担う。

### Monad と Sui：オプション型の選択に向く

両チェーンの技術構造は高性能取引を支えられるが、初期成長はインセンティブに左右され得る。ステーブルコイン、マーケットメーカー、自然な継続利用の検証が必要だ。試験市場、エコシステム提携、第2の展開先に適するが、資金とマーケットメイクの確約がなければ唯一の選択にはしない。

## 新規 Perp で最も難しいのはマッチングではない

Perp チームはマッチング性能を過大評価し、テールリスクを過小評価しがちだ。極端な相場を乗り切れるかは次で決まる。

- 指数価格を操作できないか。
- オラクル遅延時にどう縮退するか。
- マーケットメーカーの注文取消後、流動性の空白をどう扱うか。
- 清算エンジンが連鎖的な担保不足を生まないか。
- 保険基金がどの規模の不足を補えるか。
- 複数市場のヘッジの両脚が切り離されないか。
- 少数口座が資金調達率を操作できないか。

TPS は注文処理を速めるが、これらを自動解決しない。リスクを分離できない高速 Perp DEX は、誤りをより速く増幅するだけだ。

## 公開前の Go / No-Go

### 進めてよい条件

- 明確で計測可能な集客入口が少なくとも1つある。
- マーケットメーカーが実在庫と気配値を約束する。
- 独自資産、地域市場、取引用途がある。
- 対象チェーンに十分なステーブルコインと現物深度がある。
- 価格、速度、資産範囲、体験で明確に差別化できる。
- オラクル、清算、保険基金、極端な相場の試験を終えている。

### 延期すべき条件

- Uniswap、PancakeSwap、Jupiter、Hyperliquid の複製にすぎない。
- ウォレット、トレーダー、プロトコル、取引所の集客経路がない。
- 取引量が主にトークン報酬に依存する。
- 公開前にマーケットメーカーが決まっていない。
- TPS の議論のみで完全なリスクエンジンがない。
- 最初から複数チェーンに展開し、資金とチームの注意が分断される。
- 1か月の成長データで長期需要を証明する。

## 結論

チェーン選択の中心は、最高性能を探すことではなく、チームの資源に合う市場構造を探すことだ。

- Rust、取引ボット、マーケットメーカー、新規資産の資源があるなら **Solana**。
- Solidity、USDC、ウォレット商品、法令対応能力があるなら **Base**。
- 全インフラを作り直さず特定分野の Perp を作るなら **Hyperliquid HIP-3**。
- Binance エコシステムや地域の集客があるなら **BSC** を最上位へ。
- 機関、RWA、ステーブルコイン、資本決済なら **Ethereum + Base** の階層構造。

**最低限の判断：利用者がどこから来るか、誰が流動性を供給し、極端な相場の負担を誰が負うかを先に示す。その後にチェーンを議論する。性能は必要条件だが、集客とリスク対応こそ長期的な堀となる。**
