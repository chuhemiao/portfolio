## TL;DR

- **时间窗口极短**：20:24 清空 → **20:32** 分析师首次公开示警（8 分钟）→ **21:01** 发行方开始冻结（37 分钟）。**资金离场与止损生效之间差了半小时。**
- **规模**：独立链上核算 **56.43 亿美元**（已剔除找零与内部转账），Arkham 的 `binance-hacker-1029` 集群（55 个地址）持仓约 **58.4 亿**。
- **冻结约 26.2 亿**（Tether 15.67 + Circle 8.23 + Ripple 2 + USD1 0.27），币安官方核实 **25.4 亿** —— 差异来自统计时点与地址重叠。
- **这个 45% 不是风控能力，是资产构成的偶然。** 稳定币可以冻结，**原生 BTC/ETH 不能** —— 它们仍在攻击者手中，且正被换成 ETH。
- **不是合约漏洞。** 合约没有被攻破，被攻破的是「谁有权让钱包执行代码」。机制见[配套的 EIP-7702 拆解](/zh-CN/blog/eip-7702-delegation-one-signature-drains-everything)。
- **BNB −10.0%，约为 BTC 的两倍**，且在官方声明发布后仍在下探 —— 市场不是在一次性消化利空，而是在为「提现何时恢复」持续重新定价。

## 二、链上证据：一笔交易如何搬走 25 亿

首笔清空的资产清单相当具体，这是判断「不是合约漏洞、而是钱包控制权失守」的核心依据：

| 资产 | 数量 | 备注 |
|---|---:|---|
| USDT | **16.15 亿** | 后被 Tether 冻结 |
| ETH | **167,464** | 约占该笔交易 15% 价值 |
| RLUSD | 6,260 万 | Ripple 后续冻结约 2 亿 |
| wBETH | 29,934 | 流动性质押凭证 |
| XAUt | 11,372 | 黄金代币 |
| ENA | 1.984 亿 | 后续被抛售 |
| PEPE | 7.175 万亿 | 后续被抛售 |
| UNI / LINK / AAVE | 619 万 / 226 万 / 12.79 万 | 后续被抛售 |

**单笔交易的 calldata 里是 65 个地址**：1 个 `address(0)`（ETH 占位符）+ **64 个** ERC-20，合计约 25 亿美元。公开分析里的「63 种代币」更可能是实际转账成功的数量。

链上指纹非常清晰：`Binance 14` 的代码被写成 **`0xef0100 + 63e842b0…`**（EIP-7702 委托指示符），随后由 operator 地址 `0x7c8601d4…`（Tornado Cash 出资）调用 `sweep(address,address[])`（选择器 `0x8a179be4`）完成清空。

**调用者不是账户所有者，但执行结果等同于所有者亲自操作** —— 这正是 7702 委托的设计语义。

**这不是临时起意。** 链上记录显示攻击者准备了近 **18 小时**：02:28 部署测试合约，13:51 与 16:20 在**三个自有钱包**上彩排委托与扫荡，15:59 才部署最终合约，**20:20 动手**。彩排完成到动手之间还空了 3.5 小时 —— 在等合适的执行时机。

授权交易里包含 **50 个 EIP-7702 授权**，nonce **降序**排列，**恰好只有 1 条生效**（其余 49 条 `invalid_nonce`）。降序是刻意的：升序会让命中后每条更高 nonce 依次生效，把账户 nonce 连推 15 次。

**而授权与清空是分离的两笔交易，隔了 17 个区块 / 3 分 24 秒** —— Type-4 交易在 mempool 里公开可见，那本来是一个可以拦截的窗口。逐笔拆解见[配套的技术复盘](/zh-CN/blog/eip-7702-delegation-one-signature-drains-everything)。

攻击还沿着所有权关系扩散：通过 Binance 14 对 **Hot Wallet 34**（一个智能钱包，所有者正是 Binance 14）发起调用，又转出约 **7.8–8.23 亿 USDC**。

## 三、规模：两套口径

| 口径 | 金额 | 说明 |
|---|---:|---|
| 独立链上核算 | **$5.643B** | ETH 35.28 亿 + BTC 14.49 亿（18,270 枚）+ Tron 6.28 亿 + Arbitrum/Optimism/Base 3,800 万。**已剔除找零与内部转账的重复计算** |
| Arkham `binance-hacker-1029` | **$5.84B** | 55 个地址合计持仓，其中 USDT 17.7 亿、BTC 14.4 亿、ETH 9.22 亿、USDC 8.23 亿、TRX 2.47 亿、SOL 9,460 万 |

**必须强调两件事。**

**第一，持仓市值 ≠ 已实现损失。** Arkham 的数字包含尚未卖出、且部分已被冻结的资产。币安至今未公布净损失。

**第二，这个数字不能全部归因于那一次 7702 攻击。** 50 条授权的 `chain_id` 全部是 **1** —— 按 EIP-7702，只有 `chain_id = 0` 才能跨链重放。**而比特币、Tron、Solana 根本没有 EIP-7702 这个机制。**

所以以太坊上的 25 亿有完整的授权→执行因果链，**其他链上的数字只是余额变动**，可能混着：其他热钱包的独立失守、币安自己的归集或防御性转移、用户恐慌提现，或分析师误标。

**这不是说多链损失不存在，而是说归因必须分开做。** 把 56 亿统一记在「一次 7702 攻击」名下，会高估这次攻击的技术半径，也会误导后续的防御重点。

放到历史坐标里，无论取哪个口径都刷新了纪录：

## 四、冻结：唯一真正起作用的止损

| 冻结方 | 资产 | 金额 |
|---|---|---:|
| Tether | USDT | **$1.567B** |
| Circle | USDC | $823M |
| Ripple | RLUSD | $200M |
| World Liberty / BitGo | USD1 | $27M |
| **合计** | | **$2.617B** |

币安官方核实的数字是 **25.4 亿美元**，与四家发行方公布的 26.2 亿基本吻合 —— **差异来自统计时点与地址重叠，不是矛盾。**

**结构性缺口很清楚：稳定币可以冻结，原生资产不能。**

**而这个 45% 本身就是一条信息：** 它说明被转走的资产里近一半是发行方可以单方面冻结的中心化稳定币。换个资产结构 —— 比如热钱包里原生资产占比更高 —— **同样的攻击会产生完全不同的可追回比例**。

**所以 45% 不是风控能力的体现，是资产构成的偶然结果。** 而且这个比例还在被侵蚀：攻击者已在抛售 PEPE、UNI、LINK 换成 ETH，**把可冻结资产主动转换成不可冻结资产**。

## 五、生态回应比交易所更快

- **发行方**：Tether 从 9.71 亿一路加到 15.67 亿，四家合计约 26.2 亿。
- **DeFi**：Aave 主动冻结全部 DAO 运营市场（V3/V4），暂停新增存借，**但保留提现与还款** —— 这是「切断攻击者的抵押借款通道」而非「冻结用户资产」，处置相当克制，合约本身未受影响、仓位仍超额抵押。
- **同业**：Bybit、Binance.US 均在数小时内声明未受影响，**避免了一次全行业挤兑式恐慌**。
- **做市商**：Wintermute 的 Evgeny Gaevoy 公开表示币安可承受当前损失 3–4 倍的冲击，**但建议在原因查明前不要向币安充值**。

## 七、争议与待核实

公开材料里有几处需要修正或标注不确定性，这直接影响判断：

| 说法 | 状态 | 说明 |
|---|---|---|
| EIP-7702 授权是「临时执行合约逻辑」 | **需修正** | 委托是**持久**的，直到被新授权替换或指向 `address(0)` 清除。正因如此才有「后续入账被再次扫走」 |
| 已冻结 25.4 亿美元 | **基本可信** | 与四家发行方的 26.2 亿吻合，差异属统计时点 |
| 攻击者已将部分代币换成 ETH | **可信** | Lookonchain 已记录抛售 PEPE/UNI/LINK |
| 币安用自身密钥反制、追回部分 USDC | **未证实** | 仅见社交媒体转述，无官方或链上确证 |
| 覆盖「至少 9 条链」 | **部分证实** | 有明确金额的是 ETH、BTC、Tron 及 Arbitrum/Optimism/Base |
| 总规模「超过 62 亿美元」 | **上限口径** | Arkham 集群 58.4 亿 + 后续流入可接近，但含未实现与已冻结资产 |
| 攻击者身份 / 是否内部人 | **未知** | 「私钥泄露」与「签名流程被入侵」两说并存，官方未定性 |
| 后门是否已关闭 | **未确认** | 10-30 00:10 的转入交易中 `Binance 14` 仍带 `proxy_type: eip7702`，且最近 50 笔转出里**没有指向 `address(0)` 的撤销交易** |
| 多链损失同属一次攻击 | **不成立** | 授权 `chain_id = 1`，仅限以太坊主网；BTC/Tron/Solana 无此机制 |

**另一个必须澄清的认知误区：这次不是「智能合约被黑」。** 合约没有漏洞，被攻破的是「谁有权让钱包执行代码」。

**这也是为什么损失边界如此清晰** —— 受影响的只有币安自己控制的地址，Aave、Bybit 等协议层与平台层毫发无伤。

## 八、结论

把线索按时间排开后，轮廓比最初报道清楚得多：攻击者在 **15:59** 就部署好了恶意委托合约，**20:24** 用一条由热钱包私钥签署的授权完成清空，**20:32** 才被公开察觉，**21:01** 起发行方开始冻结。

**真正被抢走的时间窗口只有几分钟，而真正能挽回损失的手段只能覆盖约 45%。**

对市场的含义分三层：

**短期**看提现恢复时点与冻结规模，决定 BNB 的折价是否继续扩大。

**中期**看币安是否公布净损失、储备证明与根因，决定这是「可控运营事故」还是「托管信任重定价的起点」。

**长期**看这次 EIP-7702 路径是否倒逼全行业重构热钱包签名架构 —— **如果不止币安一家在用「在线 EOA 直接持币」的模式，那么同类风险仍是行业级的。**

**底线判断。** 在提现恢复与损失口径落地之前，不宜把 BNB 的下跌当作「错杀」：**它跌的是平台特定风险溢价，而这个溢价要由披露质量来修复，不由时间自动修复。**

对用户而言，最现实的动作仍是分散托管、优先自托管，并且在任何「批量授权 / 账户升级」签名请求前停三秒 —— **这次事件的起点，就是一条看起来完全合法的签名。**
