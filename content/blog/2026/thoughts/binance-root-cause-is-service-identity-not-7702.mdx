> 本文基于币安 **2026-10-30 02:23 UTC** 发布的《Security Incident Update》与链上数据，行情截至 02:43 UTC。公告自身的措辞是「初步调查显示可能涉及」「未发现证据」「估算」—— **这是调查方向，不是最终结论**。币安承诺的 technical post-mortem 才是决定性文件。

## TL;DR

**被攻破的不是 EIP-7702，是一个拥有签名能力的服务身份。**

- **根因（币安口径）**：可能涉及一名 **DevOps 工程师的笔记本电脑**被攻陷，攻击者借此进入**服务容器**并提交未授权提现交易。
- **币安称未发现任何钱包私钥泄露的证据**，并已**撤销受影响地址的授权**。
- **规模**：总影响估算 **63 亿**，已冻结约 **30 亿**，净敞口约 **33 亿**，由 SAFU 与公司资金覆盖。
- **7702 的角色变了**：它不是入口，是**放大器** —— 把一笔受提现策略约束的操作，变成一次不受限额约束的代码执行。
- **它顺带解答了我上一篇留下的问题**：我指出 50 条授权的 `chain_id` 全是 1，所以多链流出「必须另有解释」。**这份公告给出了那个解释** —— 同一个提现服务，不同链，以太坊之外根本不需要 7702。
- **公告里有一道缝**：币安说攻击者「提交未授权**提现**交易」，但以太坊上那笔是 **set-code 交易**，不是提现。两者不矛盾，但复盘必须回答：**这个服务凭什么能请求一条改写账户代码的签名？**

## 一、公告拆解：七个事实，一条真正的新信息

和前两份「资金安全、正在检查」的原则性表态不同，这份公告有可核对的具体表述：

| 公告要点 | 具体表述 | 独立核验状态 |
|---|---|---|
| 根因 | 可能涉及被攻陷的 DevOps 笔记本，攻击者进入服务容器并提交未授权提现 | 初步调查；与链上「服务代签」特征一致，待技术复盘 |
| 私钥 | 未发现任何钱包私钥泄露的证据 | 外部无法验证；与「密钥未离开签名系统」相容 |
| 规模 | 估算总影响约 **63 亿** | 高于第三方的 56.4–58.4 亿；毛/净口径未说明 |
| 冻结 | 已与链上伙伴冻结约 **30 亿** | 高于此前的 25.4–26.2 亿；增量未逐项披露 |
| 覆盖 | SAFU + 公司资金承担全部损失 | 需更新版储备证明验证 |
| 处置 | 暂停存提；**撤销受影响地址授权**；联合执法与链上情报 | 撤销声明待链上独立复核 |
| PoR | 修复完成后发布更新版储备证明 | **无时间表** |

**真正的新信息只有第一条：根因从「未知」变成了「运维终端与服务凭证」。** 其余数字都是对既有事实的确认或上修。

**「撤销受影响地址授权」这句话值得单独拎出来。** 公告全文没有出现 EIP-7702 字样，但「地址授权」正是 7702 委托的链上用语 —— **这等于币安间接承认了以太坊上的攻击路径是代码委托，而不是普通的私钥转账。**

## 二、根因链：从运维笔记本到签名能力

把因果链展开，大致五步：

```text
DevOps 工程师笔记本
  → VPN / kubeconfig / CI-CD token / 服务账号
  → 提现或签名服务容器
  → 签名服务 / HSM / MPC
  → Type-4 授权（50 条 nonce）
  → 热钱包代码被改写 → 批量扫荡
```

**第一步，为什么是 DevOps 笔记本。** 这类终端握着的是自动化系统的钥匙，而不是币本身：Kubernetes 的 kubeconfig、CI/CD 部署令牌、SSH 私钥、VPN 凭据、密码管理器、监控后台。攻陷一台这样的机器，等价于拿到一个高权限服务身份。

**公告没说入侵方式（钓鱼、恶意软件、供应链），也没说驻留时间** —— 而这两个信息决定了还有多少其他服务需要排查。

**第二步，服务容器为什么危险。** 它不是「一台机器」，而是一个拥有云身份的工作负载。攻击者拿到容器后，**未必要偷私钥** —— 他可以用容器的 IAM 角色或服务账号，向签名服务发起请求。

**「未发现私钥泄露」与这条路径完全相容：密钥没有离开 HSM，但签名能力被借用了。**

**这比私钥泄露更难防 —— 轮换私钥没有用，必须切断服务身份。**

**第三步，7702 为什么能绕过提现风控。** 这是整条链里最容易被低估的技术细节。

提现系统的策略引擎通常检查交易的 `to`、`value`、`data`、白名单和限额。而一条 Type-4 交易：

| 字段 | 值 | 策略引擎看到的 |
|---|---|---|
| `to` | 热钱包自己 | 自己转给自己 |
| `value` | 0 | 没有金额 |
| `data` | `0x`（空） | 没有调用 |
| `authorization_list` | **真正的内容在这里** | **通常不解析** |

**对只解析 calldata 的策略来说，这看起来像一笔「自己转给自己 0 元」的无害交易。** 签名一旦通过，代码被写入，**提现限额就彻底失效了** —— 后续的清空不再经过提现系统，而是直接以热钱包的身份执行代码。

**第四步，50 条 nonce 说明签字方是「接口」，不是「人」。** 如果签名侧能直连节点读取 nonce，一条就够。需要一次签 50 条，通常意味着签名服务**看不到实时链上状态**，或者需要覆盖从签名到上链的漂移。

**这与「服务容器代签」的画像高度一致：它能请求签名，但不一定能读链。** 我在[攻击链那篇](/zh-CN/blog/eip-7702-delegation-one-signature-drains-everything)里据此推断「指向被侵害的签名基础设施而非被复制的私钥」—— 公告的方向与此一致。

**第五步，「未发现私钥泄露」的三种解释。**

1. HSM/MPC 签名预言机被冒用，密钥从未离开；
2. 软件密钥在容器或内存中被原地使用，未被复制；
3. 密钥确实泄露，但调查尚未发现。

**如果公告所说的撤销已经生效、且攻击者没有再次委托，则前两种更可能** —— 因为完全持有私钥的人可以在撤销后立刻重新装回后门。我在攻击链篇里把「未观察到再委托的拉锯」当作偏向签名通道被利用的弱证据，**公告给了它一个更强的解释框架。**

## 三、公告没有解释的那道缝

**币安说攻击者「提交未授权提现交易」，但以太坊上那一笔是 set-code 交易，不是提现。**

两者并不矛盾 —— 提现服务可能同时具备构造 Type-4 交易的能力。但技术复盘必须说明：

**这个服务为什么能请求一条改写账户代码的签名？**

这才是真正的控制失效点。「提现」和「把账户代码指向一个未验证合约」不在同一个风险等级上，**却共用了同一套签名策略**。

## 四、规模对账：63 亿是毛口径，净敞口约 33 亿

63 亿是这份公告里最容易被误读的数字：

| 口径 | 数值 | 说明 |
|---|---:|---|
| **币安公告** | **$6.3B** | 「估算总影响」，未说明是否扣除冻结与回流 |
| Arkham 集群 | $5.84B | 55 个地址，含 USDT、BTC、ETH、USDC、TRX、SOL |
| BWEnews | $5.64B | ETH、BTC、Tron、L2 分链核算 |
| CoinDesk | $5.7B | 媒体汇总 |
| Blockaid | $3.3B | 较早时点 |
| DeltaOne | $2.77B | 五链估算，明显偏窄 |

**从公告「另列约 30 亿已冻结」的写法看，63 亿更像毛流出，不是净损失。** 按此计算：

```text
63 亿  总影响（毛）
−30 亿  已冻结
─────
 33 亿  理论净敞口
```

**但这既不是最终损失，也不是可立即回收的现金。**

冻结的构成可以部分对账：此前 Tether 约 15.67 亿、Circle 8.23 亿、Ripple 2 亿 RLUSD、World Liberty/BitGo 2,700 万，**合计约 26.2 亿**。公告的 30 亿意味着还有约 **3.8 亿**的增量冻结未逐项披露。

**更关键的是，冻结不等于追回。** USDT、USDC、RLUSD 可以在合约层冻结，**但 BTC 和 ETH 不能**。BWEnews 估算的 18,270 枚 BTC（约 14 亿美元）只能通过交易所入境时扣押或执法行动追回 —— 这部分资产目前是「可追踪但未冻结」。

**所以 30 亿冻结大概率集中在稳定币，真正的现金回收仍取决于发行方配合与执法进度。**

公告没有披露 SAFU 的具体余额。公开报道提到的 SAFU 转换计划是 **10 亿美元级别**；若按此粗估，33 亿净敞口仍需公司资金覆盖约 **23 亿**。对币安这种体量并非不可承受，**但「可承受」与「已覆盖」是两件事 —— 更新版 PoR 是唯一的验证方式，而公告只给了「修复完成后」的时间条件，没有日期。**

## 五、链上复核：公告与证据的四个交点

| UTC | 事件 |
|---|---|
| 10-29 15:59 | 攻击者部署恶意委托合约 `0x63e842…` |
| 10-29 20:20:59 | 50 条授权上链，仅 nonce `18,914,809` 生效 |
| 10-29 20:24:23 | 主扫荡，约 25 亿美元，手续费约 $0.91 |
| 10-29 20:32 | 社区首次公开曝光 |
| 10-29 21:01 | Tether 开始冻结 |
| 10-29 22:33 | 币安第一份声明：安全检查、提现待恢复 |
| **10-30 00:10** | **链上最后确认：`Binance 14` 仍处于 7702 委托状态** |
| **10-30 02:23** | **《Security Incident Update》：根因、63 亿、30 亿冻结、已撤销授权** |
| 10-30 02:32 | PREDICT 上币推迟，运营影响外溢 |

**交点一：7702 路径已被链上完整证实。** 50 条授权、1 条生效、`0xef0100‖0x63e842…` 的代码指示符、3 分 24 秒后的 sweep、以及随后 3.5 小时内 12 次扫荡（多次是 23,100 gas 的空轮询），都与「持久委托 + 自动化机器人」一致。

**交点二：撤销声明尚未独立复核。** 公告称已撤销，但链上最后一次确认委托有效是在 **00:10 UTC**，撤销应发生在此后。

**撤销交易可能由服务地址代发，因此不会出现在 `Binance 14` 的转出列表里** —— 要独立确认，需要直接读取该地址的代码（按规范 `EXTCODESIZE` 返回 23，可以直接解出委托目标），或等 post-mortem 给出交易哈希。**在拿到哈希之前，「已撤销」仍属公司声明。**

**交点三：63 亿与第三方集群差约 4.6 亿美元。** 可能来自未纳入 Arkham 集群的地址、其他链的流出，或统计时点差异。**公告没有给出分链、分资产明细，所以无法逐项对账。**

**交点四：暂停范围扩大了。** 第一份声明只说提现暂停，新公告变成**存款与提现同时暂停**，并推迟了新币上线。

**这说明币安不是在「等链上确认」，而是在重建或隔离整条提现链路。** 从风控角度合理，从流动性角度是一个需要盯住的信号。

## 七、未解的六个问题

公告给出了方向，没有给出证据。以下是判断「可控」能否成立的关键：

1. **笔记本何时、如何被攻陷？攻击者驻留了多久？** 如果入侵发生在数周前，其他服务和终端都要排查。
2. **哪个服务账号或容器拥有签名权限？权限边界和审批链是什么？** 这是整条链的咽喉。
3. **签名策略为什么放行 50 条授权？** 是否解析 `authorization_list`？为什么没有对「未验证合约 + 50 个 nonce」告警？
4. **私钥在 HSM/MPC 还是软件里？日志能否证明它没有被导出？** 「未发现泄露」需要日志支撑，而不是结论。
5. **BTC、Tron 等链的流出是否来自同一服务？** 如果是，说明根因是**跨链的提现服务**，而不是一条 `chain_id=1` 的授权 —— 这也正好解释了为什么 7702 只出现在以太坊。
6. **63 亿是毛还是净？30 亿冻结的逐项清单与可回收性如何？PoR 何时发布、是否覆盖负债端？**

## 八、结论

**这份公告的价值不在于「63 亿」这个数字，而在于它把根因从密码学拉回到了运维。**

不是 EIP-7702 被攻破 —— **是一个拥有签名能力的服务身份被攻破。**

7702 只是放大器：它让一次受限额约束的提现，变成一次不受限额约束的代码执行。**真正需要修的是服务身份、签名策略和终端安全，而不是协议本身。**

对行业，这次事件给出了一个明确的教训：**代码委托必须被当作最高权限操作来治理。** 它和「转账」不在同一个风险等级，**不能共用同一套签名策略。**

**底线判断。** 在技术复盘和更新版 PoR 公布之前，「可控」只是公告，不是结论。接下来只看三个信号：**链上是否出现可核验的撤销交易、PoR 是否覆盖负债端、提现是否在数日内恢复。** BNB 的 **$678** 是信心线，**$760** 是修复线。
