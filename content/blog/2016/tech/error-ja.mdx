## ページの HTTP ステータス検索について
1. Ctrl+F でステータスコードを直接検索することをおすすめする。
2. サイトのページを表示するようサーバーに要求すると、サーバーは HTTP ステータスコードを返す。
3. ブラウザーでページを開く場合や Googlebot が取得する場合など、サーバーにページ表示を要求すると、HTTP ステータスコードで応答する。
4. コードは要求の状態を示し、Googlebot にサイトや対象ページの情報を伝える。
5. よく使うコード：
200 — サーバーがページを正常に返した。
404 — 要求したページが存在しない。
503 — サーバーが一時的に利用できない。

## 1xx（一時的な応答）
一時的な応答を表し、処理を続けるために要求側の操作が必要となるコード。
コードと説明：
100（Continue）：要求を続ける。サーバーは最初の部分を受信し、残りを待っている。
101（Switching Protocols）：要求側がプロトコル変更を求め、サーバーが確認して切り替えを準備した。

## 2xx（成功）
サーバーが要求を正常に処理したことを示す。
コードと説明：
200（OK）：要求を正常に処理した。通常はページを提供する。robots.txt なら、Googlebot がファイルを取得できたことを示す。
201（Created）：要求が成功し、新しいリソースを作成した。
202（Accepted）：要求を受け付けたが、まだ処理していない。
203（Non-Authoritative Information）：要求は成功したが、返す情報が別の情報源に由来する可能性がある。
204（No Content）：正常に処理したが、内容は返さない。
205（Reset Content）：正常に処理したが、内容は返さない。204 と異なり、フォームを消して再入力するなど、文書ビューのリセットを要求する。
206（Partial Content）：GET 要求の一部を正常に処理した。

## 3xx（リダイレクト）
要求を完了するには追加操作が必要。通常、これらは恒久的なリダイレクトである。Google は要求ごとのリダイレクトを 5 回未満にすることを推奨する。ウェブマスターツールで、Googlebot のリダイレクト先の取得に問題がないか確認できる。
コードと説明：
300（Multiple Choices）：複数の処理を選べる。サーバーが要求側（User agent）に応じて選ぶか、一覧を返して要求側に選ばせる。
301（Moved Permanently）：ページが恒久的に移転した。GET や HEAD に対して返すと、新しい場所へ自動的に転送する。Googlebot に恒久的な移転を伝える際に使う。
302（Moved Temporarily）：現在は別の場所から応答するが、今後の要求は元の場所へ送る。GET・HEAD に対する 301 と同様、別の場所へ自動転送する。ただし Googlebot は元の場所を取得・インデックスし続けるため、恒久的移転の通知には使わない。
303（See Other）：応答を得るには別の場所へ独立した GET 要求を送る。HEAD 以外の要求では別の場所へ自動転送する。
304（Not Modified）：前回の要求以降、ページは変更されていない。ページ内容は返さない。
前回取得以降に変更がなければ、この応答を返すよう設定する（If-Modified-Since HTTP ヘッダー）。前回のクロール以降に変更がないと Googlebot に伝えることで、帯域と処理の負担を減らせる。
305（Use Proxy）：ページにはプロキシ経由でのみアクセスできる。応答で使用するプロキシも示す。
307（Temporary Redirect）：現在は別の場所から応答するが、今後は元の場所を使う。GET・HEAD に対する 301 と同様、自動転送する。ただし Googlebot は元の場所を取得・インデックスし続けるため、恒久的移転の通知には使わない。

## 4xx（要求エラー）
要求に問題があり、サーバーの処理を妨げた可能性を示す。
コードと説明：
400（Bad Request）：要求の構文を理解できない。
401（Unauthorized）：認証が必要。ログイン後にサーバーがこのページ応答を返す場合がある。
403（Forbidden）：サーバーが要求を拒否した。Googlebot が有効なページを取得しようとしてこの状態になる場合（Google ウェブマスターツールの診断 > ウェブクロールで確認可能）、サーバーやホストが Googlebot のアクセスを拒否しているかもしれない。
404（Not Found）：要求されたページが見つからない。存在しないページへの要求では通常このコードを返す。
robots.txt があるのにこの状態なら、名前か配置先が誤っている可能性がある。ファイルはトップレベルのドメインに配置し、robots.txt と名付ける。
Googlebot が取得する URL でこの状態になる場合（診断の HTTP エラーページ）、別のページの古いリンクや入力ミスのある無効なリンクをたどった可能性がある。
405（Method Not Allowed）：指定したメソッドが無効になっている。
406（Not Acceptable）：要求した内容の特性ではページを返せない。
407（Proxy Authentication Required）：401 に似ているが、プロキシでの認証が必要。使うプロキシも応答に示す。
408（Request Timeout）：要求を待つ間にタイムアウトした。
409（Conflict）：完了時に競合が起きた。サーバーは応答に競合の詳細を含める必要がある。以前の要求と競合する PUT でこのコードを返し、相違点の一覧を示す場合がある。
410（Gone）：リソースが恒久的に削除された。404 に似ているが、以前は存在したものに使うことがある。恒久的な削除の場合は、301 で新しい場所を示す。
411（Length Required）：無効な Content-Length ヘッダーを持つ要求は受け付けない。
412（Precondition Failed）：要求側が指定した前提条件を満たせなかった。
413（Request Entity Too Large）：要求エンティティーが大きすぎて、処理能力を超えている。
414（Request URI Too Long）：URI（通常は URL）が長すぎて処理できない。
415（Unsupported Media Type）：要求の形式をページがサポートしていない。
416（Requested Range Not Satisfiable）：ページの範囲指定が無効である。
417（Expectation Failed）：Expect 要求ヘッダーの条件を満たせなかった。

## 5xx（サーバーエラー）
要求を処理する際に内部エラーが発生した。要求ではなくサーバー側の問題である可能性がある。
コードと説明：
500（Internal Server Error）：サーバーでエラーが発生し、完了できなかった。
501（Not Implemented）：必要な機能がない。たとえば要求メソッドを認識できない場合。
502（Bad Gateway）：ゲートウェイやプロキシとして動作中、上流から無効な応答を受け取った。
503（Service Unavailable）：過負荷や保守により利用できない。通常は一時的な状態。
504（Gateway Timeout）：ゲートウェイやプロキシとして動作中、上流の要求を時間内に受け取れなかった。
505（HTTP Version Not Supported）：要求で使われた HTTP バージョンをサポートしていない。
